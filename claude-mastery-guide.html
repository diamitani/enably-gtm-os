Getting Started with Claude Code

Claude Code is a command-line tool that lets you interact with Claude from your terminal. It's perfect for integrating Claude into scripts, automation workflows, and development environments.

Installation

Claude Code is installed via npm (Node Package Manager). Make sure you have Node.js 18+ installed.

bash 
npm install -g @anthropic-ai/claude-code

Once installed, verify the installation:

bash 
claude --version

Initial Configuration

Before using Claude Code, you need to authenticate with your API key:

bash 
claude init

This will prompt you to enter your Anthropic API key. You can find it in your Anthropic dashboard.

Basic Commands

Command Purpose Example
claude chat Start an interactive conversation claude chat
claude code Generate or work with code claude code "create a Node.js server"
claude analyze Analyze files or content claude analyze data.csv
claude write Generate text content claude write "marketing email"
claude --help Show all available commands claude --help

Your First Conversation

bash 
claude chat

This launches an interactive chat session where you can:

  • Ask questions and get detailed answers
  • Request code generation or debugging
  • Get analysis and recommendations
  • Have multi-turn conversations with context preservation

Key Slash Commands

Command Function
/help Display available commands
/clear Clear conversation history
/exit Exit the chat session
/model Switch to different Claude model
/file [path] Load a file into context
/compact Show compact output (less verbose)

Working with Files

Claude Code can read and analyze files from your current directory. When you ask Claude to work with a file:

bash 
claude code "analyze the errors in app.js"

Claude will:

  1. Read the file from your filesystem
  2. Analyze the content
  3. Provide fixes or explanations
  4. Optionally create or modify files as needed

When working in a project directory with a CLAUDE.md file (covered in the next chapter), Claude automatically uses that context to understand your project structure and preferences.

CLAUDE.md - Your AI's Brain

CLAUDE.md is a markdown file that gives Claude persistent context about your project. Think of it as a set of instructions that Claude reads before every interaction, helping it understand your project structure, preferences, and constraints.

What is CLAUDE.md?

The Intelligence Layer

CLAUDE.md is a markdown configuration file that sits at the root of your project (or in ~/.claude/ for global settings). It tells Claude how to work with your specific codebase and team.

Where to Place It

Location Scope Use Case
./CLAUDE.md Project-level Specific to one project or repository
~/.claude/CLAUDE.md Global Applies to all projects on your machine
./src/CLAUDE.md Directory-level Specific guidance for a subdirectory

What to Include in CLAUDE.md

markdown 
# Project Context

## Project Name
[Your Project Name]

## Technology Stack
- Frontend: React 18
- Backend: Node.js/Express
- Database: PostgreSQL
- Hosting: AWS

## Coding Standards
- Use TypeScript for all new code
- Follow ESLint config: .eslintrc.json
- Write tests with Jest
- Use prettier for formatting

## File Structure
- /src - Application source code
- /api - API routes
- /components - React components
- /utils - Shared utilities
- /tests - Test files

## Key Files to Know
- package.json - Dependencies and scripts
- tsconfig.json - TypeScript configuration
- .env.example - Environment variables

## Team Preferences
- Use async/await over promises
- Keep functions under 50 lines
- Comment complex business logic
- Update tests when changing functionality

## Common Patterns
- API responses use standard envelope: { status, data, error }
- All dates use ISO 8601 format
- Error codes: 400 (bad request), 401 (auth), 500 (server)

## Gotchas
- Database migrations must be backward compatible
- Never modify production data in scripts
- API rate limits: 1000 req/min per user

Best Practices

  • Keep it focused: Don't dump your entire company handbook in CLAUDE.md. Include only what's relevant to daily work.
  • Update regularly: As coding standards or team processes change, update CLAUDE.md immediately.
  • Use sections: Organize with clear headers and bullet points for easy scanning.
  • Include examples: Show Claude what good looks like with code examples or sample content.
  • Link to resources: Reference other files in your project that Claude might need.
  • Document exceptions: Call out special cases or gotchas that Claude needs to know.

Skills - Teaching Claude New Tricks

Skills are the way to teach Claude how to perform specialized tasks. A Skill is just a folder containing a SKILL.md file - it's an instruction manual packaged and ready to deploy.

What is a Skill?

Packaged Instructions

A Skill is a reusable instruction set that tells Claude exactly how to perform a specific task. Unlike generic prompts, Skills are versioned, shareable, and discoverable.

Skill Folder Structure

bash 
my-skill/
├── SKILL.md          # Main skill instructions (required)
├── scripts/          # Helper scripts (optional)
│   ├── process.js
│   └── validate.js
├── references/       # Documentation files (optional)
│   ├── best-practices.md
│   └── examples.md
└── assets/           # Files, templates (optional)
    ├── template.txt
    └── data.json

Creating Your First Skill

Let's create a content-creator Skill for GTM teams:

markdown 
---
name: Content Creator
description: >
  Writes marketing content including blog posts, emails, social media,
  and case studies. Uses brand voice and follows company guidelines.
version: 1.0.0
category: marketing
---

# Content Creator Skill

You are an expert content creator for our marketing team. Your job is to write compelling,
on-brand content that drives engagement and conversions.

## How to Use This Skill

When asked to write content, follow these steps:

1. Clarify the content type (blog, email, social, case study, etc.)
2. Identify the target audience
3. Gather any relevant brand guidelines or positioning documents
4. Write the content in the specified format
5. Optimize for the platform (character limits, formatting, etc.)
6. Suggest a CTA (call-to-action)

## Content Templates

### Blog Post Structure
- Eye-catching headline (6-8 words)
- 2-3 sentence hook
- 3-5 main sections with subheadings
- Real examples or data points
- Conclusion with next steps
- Meta description (160 characters max)

### Email Subject Lines
- Keep under 50 characters
- Include power words (new, limited, exclusive, free)
- Ask a question or create curiosity
- A/B test variations

### Social Media Posts
- Twitter (280 chars): Conversational, with 1-2 hashtags
- LinkedIn (3000 chars): Thought leadership, professional tone
- Instagram (2200 chars): Visual-first, emotional connection

## Tone and Voice

- Professional but approachable
- Data-driven (include metrics when possible)
- Customer-centric (focus on benefits, not features)
- Action-oriented (use strong verbs)

## Never
- Use generic buzzwords without context
- Over-hype features without proof
- Write in first person (use "you" not "I")
- Forget to include the CTA

## Quality Checklist
- [ ] Follows brand voice
- [ ] Has clear CTA
- [ ] Optimized for platform
- [ ] Includes proof points or examples
- [ ] No typos or grammatical errors
- [ ] Matches intended audience

YAML Frontmatter Explained

Every SKILL.md file starts with a YAML frontmatter section:

Field Type Purpose Example
name string Display name of the skill Content Creator
description string What the skill does (shown to users) Writes marketing content
version semver Version number for updates 1.0.0
category string Skill category/type marketing, development
tags array Searchable keywords [content, email, blog]

Installing Skills

Skills are installed through Claude Code settings:

bash 
# Navigate to your skills directory
cd ~/.claude/skills

# Copy a skill folder here
cp -r ~/my-projects/content-creator .

# Or create a new skill from scratch
mkdir email-drafter && cd email-drafter
# Create SKILL.md in this directory

Once installed, you can invoke skills:

bash 
claude use content-creator "Write a blog post about AI in marketing"

Writing Effective Skill Descriptions

A good skill description should answer three questions:

  1. What does it do? Be specific and concrete
  2. When should I use it? Describe the use case
  3. What are the key capabilities? List main features
💡 Example
❌ Bad: "Analyzes data" ✓ Good: "Analyzes CSV files to identify trends, anomalies, and correlations. Use this when you need statistical insights from sales or marketing data. Can generate charts and recommendations."

MCP Servers - Connecting Claude to Everything

MCP (Model Context Protocol) is a standardized way for Claude to connect to external tools, services, and data sources. Think of it as giving Claude access to your company's ecosystem.

What is MCP?

The Integration Layer

MCP is like a universal adapter that lets Claude talk to any tool - GitHub, Slack, Notion, Jira, Google Drive, and more. You configure these once, and Claude can use them in any conversation.

The Kitchen Analogy

🍳 Kitchen Analogy
MCP Servers = Professional Kitchen
- Ingredients: Data from your tools (emails, documents, tasks)
- Tools: APIs and integrations available to Claude
- Equipment: The infrastructure for operations

Skills = Recipes
- How to combine ingredients with tools
- Step-by-step instructions for specific outcomes

Together: Kitchen + Recipes = Complete culinary capability

Common MCP Servers

Server What It Does Best For
GitHub Read/write code, issues, PRs Developer teams
Slack Send messages, read channels Team communication
Notion Read/write databases and pages Knowledge management
Linear Create/update issues Issue tracking
Jira Read/write issues and tickets Enterprise project management
Asana Manage tasks and projects Work management
Google Drive Read/write docs and files Document collaboration
HubSpot Access CRM data Sales and marketing

Adding MCP Servers

Add MCP servers via the command line:

bash 
claude mcp add github
claude mcp add slack
claude mcp add notion
claude mcp add asana

Claude will prompt you to authenticate with each service using your credentials or API keys.

Configuration File

MCP servers are configured in ~/.claude.json:

json 
{
  "mcpServers": {
    "github": {
      "type": "stdio",
      "command": "node",
      "args": ["~/.claude/servers/github/index.js"],
      "env": {
        "GITHUB_TOKEN": "ghp_xxxxxxxxxxxx"
      }
    },
    "slack": {
      "type": "stdio",
      "command": "node",
      "args": ["~/.claude/servers/slack/index.js"],
      "env": {
        "SLACK_TOKEN": "xoxb-xxxxxxxxxxxx"
      }
    },
    "notion": {
      "type": "stdio",
      "command": "node",
      "args": ["~/.claude/servers/notion/index.js"],
      "env": {
        "NOTION_TOKEN": "secret_xxxxxxxxxxxx"
      }
    }
  }
}

Agents & Autonomous AI

Agents are specialized AI assistants that operate independently on specific tasks. Unlike regular conversations where you guide Claude, Agents work autonomously to achieve goals.

What Are Agents?

AI Team Members

An Agent is an AI assistant configured for a specific purpose (content creation, data analysis, customer support, etc.). Agents can make decisions, use tools, and operate without constant human guidance.

Types of Agents

Agent Type Purpose Independence Level
General-purpose Flexible, handles various tasks High (requires clear instructions)
Specialized Focused on one domain (e.g., content) High (pre-configured for the domain)
Subagent Works with other agents in workflows Medium (coordinated by parent agent)
Monitoring Agent Watches systems and alerts Continuous (always running)

Creating a Custom Agent

Agents are defined in markdown files with YAML frontmatter:

markdown 
---
name: Content Agent
description: Creates and publishes marketing content autonomously
model: claude-3-5-sonnet
temperature: 0.7
tools: [slack, notion, github]
mcpServers: [slack, notion]
---

# Content Agent

You are an autonomous content creation agent for our marketing team.

## Your Goals
1. Monitor the content calendar (Notion)
2. Create content based on scheduled items
3. Review content quality
4. Publish to appropriate channels
5. Notify team of completion (Slack)

## Daily Workflow
- Check Notion for today's content tasks
- If task exists:
  - Gather context and references
  - Write content using Content Creator skill
  - Review against brand guidelines
  - Publish to the designated channel
  - Send completion notification to Slack
- If no tasks, send a summary of upcoming content

## Tools You Have Access To
- \`slack\`: Send messages and read channels
- \`notion\`: Read and update content calendar
- \`github\`: Check brand assets and templates

## Quality Standards
- All content must pass brand voice check
- Include data/examples when possible
- CTA is clear and compelling
- Images are optimized and branded

## Decision Making
- If unsure about tone: ask in Slack #content-review channel
- If task is blocked: log to Notion and notify @content-lead
- If quality issue: revise and try again before publishing

Agent Configuration Fields

Field Type Purpose
name string Agent identifier
description string What the agent does
model string Claude model to use
temperature 0.0-1.0 Creativity level (0=precise, 1=creative)
tools array Tools the agent can use
mcpServers array MCP servers to connect

Automations with n8n

n8n is a visual workflow automation platform that integrates with Claude. It lets non-technical people build complex automations without writing code.

What is n8n?

Visual Workflow Builder

n8n is like Zapier or Make, but more powerful and self-hostable. You design workflows visually by connecting nodes, and n8n executes them automatically on a schedule or trigger.

Installation

Install n8n globally via npm:

bash 
npm install -g n8n
n8n start

Or use Docker for easier management:

bash 
docker run -it -p 5678:5678 -v ~/.n8n:/home/node/.n8n n8nio/n8n

Visit http://localhost:5678 to access the UI.

Connecting Claude to n8n

Add Claude via HTTP Request node:

json 
{
  "method": "POST",
  "url": "https://api.anthropic.com/v1/messages",
  "headers": {
    "x-api-key": "sk-ant-...",
    "anthropic-version": "2023-06-01",
    "content-type": "application/json"
  },
  "body": {
    "model": "claude-3-5-sonnet-20241022",
    "max_tokens": 1024,
    "messages": [
      {
        "role": "user",
        "content": "{{ $json.task }}"
      }
    ]
  }
}

bash

Claude will design the workflow, and n8n will execute it automatically.

Building Your First Automation

Step-by-step guide:

  1. Define the trigger: What event starts this workflow? (schedule, webhook, new data, etc.)
  2. Gather inputs: What data do you need? (from where?)
  3. Call Claude: Use HTTP Request node to invoke Claude API
  4. Process output: Format Claude's response
  5. Take action: Send to Slack, update database, email, etc.
  6. Test: Run the workflow manually first
  7. Schedule: Set the trigger and activate

n8n Best Practices

  • Error handling: Add "On Error" nodes to handle failures gracefully
  • Logging: Use Debug nodes to track workflow execution
  • Rate limits: Add delays between Claude calls if processing many items
  • Testing: Always test with real data before activating
  • Documentation: Add notes to complex workflows explaining logic
  • Monitoring: Check n8n logs regularly for errors or slowdowns
✓ Pro Tip
Start with simple 3-node workflows (trigger → Claude → action). Once you're comfortable, build more complex ones with branching logic and error handling.

Step-by-Step: Blog to Video Pipeline

Goal: One blog idea → Blog post → Email → Social posts → Marketing video → Slack notification

  1. Input: Team adds blog topic to Notion calendar
  2. Trigger: n8n detects new item, calls Claude with blog-writer skill
  3. Research: Claude (via MCP) reads existing posts and brand guidelines
  4. Writing: Claude generates 2000-word blog post
  5. Publish: n8n commits blog to GitHub (which deploys to website)

Troubleshooting Common Issues

Check your API key is correct and active. Run: claude init and re-enter your key.

Verify authentication token is current. Many services rotate tokens after 30 days. Re-run: claude mcp add service-name

Check the execution logs in n8n UI. Add Debug nodes before and after Claude calls to track data flow.

Break large files into chunks and process separately, or use a faster model (Haiku) for initial processing.
